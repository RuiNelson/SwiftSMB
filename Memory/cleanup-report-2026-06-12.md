# SwiftSMB Cleanup/Simplification Report (2026-06-12)

Generated by fanning out 4 review agents over the package source (~8.6k lines).
Findings are research only — nothing has been changed. Ordered roughly by
impact within each area.

**Constraint: the public API must be preserved.** All findings below are
internal-only refactors (Bridge layer, private/internal helpers, file-private
state machines). Connection-Conv.swift item 3 (consolidating
`acceptedReadBlockSize`/`acceptedWriteBlockSize` var+method overloads) is the
one item that touches public API surface — if implemented, it must be done by
keeping both existing public entry points (e.g. keep the computed `var` as a
thin wrapper calling the method with a default argument) rather than removing
either.

## Bridge layer (`Sources/SwiftSMB/Bridge/`)

1. **Dead code**: `Bridge.swift:31-35` `waitForAllOperationsToEnd()` is a
   no-op that just syncs on the bridge queue and returns `0`. Looks like
   leftover from the DataPipe refactor. Verify no callers, then delete.
2. **Duplicated callback boilerplate**: ~10+ near-identical closures across
   `Bridge.swift` (lines ~756-816), `Bridge-Locks.swift`, `Bridge-Links.swift`,
   `Bridge-Notifications.swift` repeat
   `if state.status == SMB2_STATUS_SUCCESS { state.status = status }`
   (sometimes with `state.isFinished = true`). Add `PendingOperationState`
   helpers (`recordStatus(_:)`, `finish(_:)`) to collapse each callback to a
   one-liner (~40 lines saved).
3. **Duplicated read/write paths**: `Bridge.swift:413-483` — four nearly
   identical read/write functions (with/without offset) share the same
   bind-memory/call/check-status shape. Factor into one private helper
   parameterized by the actual smb2 call.
4. **Repeated manual cleanup in `_serverSideCopy`**: `Bridge.swift:1215-1295`
   repeats `_ = try? check(smb2_close(...))` ~5 times across error paths in
   slightly different orders. A `closeQuietly(_:)` helper or defer-based
   cleanup would reduce risk of missing a close on new error paths.
5. **`BridgeTypes.swift:478-620`** — ~140 lines of debug-formatting free
   functions (`makeDebugString`, `hexString`, `secName`, etc.) used only by
   `Context.debugDescription`. Consider moving to a separate file (e.g.
   `Bridge-Context+Debug.swift`) so `BridgeTypes.swift` stays focused on type
   declarations.
6. **Docs drift**: AGENTS.md's project tree still references
   `SMB2BridgeTypes.swift` / `SMBError+Bridge.swift`, but the actual files are
   `BridgeTypes.swift` / `Extensions/SMB.Error.swift`. Reconcile.
7. Minor: `Bridge-ShareEnum.swift:112-114` private helper `string(from:)`
   could be renamed `decodeUTF16String(from:)` to avoid shadowing `String`.

## Connection / Configuration / Transfer (`PublicAPI/Connection*.swift`, `Configuration.swift`)

1. **No-op catch**: `Connection.swift:383-399` `itemExists` has a trailing
   `catch { throw error }` that does nothing — remove.
2. **Repetitive oplock switch**: `Connection.swift:196-217` `openFile`'s
   oplock switch repeats `bridgeLeaseState = []; leaseKey = nil` in 4 of 5
   cases. Introduce a `bridgeValue` mapping (matching the convention used for
   `Dialect`/`AuthenticationMethod`) and handle `.lease` separately
   (~15 lines saved).
3. **Duplicated read/write block-size API**: `Connection-Conv.swift:18-33`
   and `:153-177` define both a computed `var acceptedReadBlockSize`/
   `acceptedWriteBlockSize` (throws, no args) and a method of the same name
   taking an optional preferred size — duplicated doc blocks for one
   operation. Consolidate to a single method with a default parameter.
4. **Progress-tracking duplication**: `Connection-Conv-Transfer.swift:246-341`
   — `transferRemoteFileToWriter` and `transferReaderToRemoteFile` both
   independently track `transferred`/`averageSpeed`/`operationStart` and call
   `continuation(...)`. Factor into a shared `ProgressTracker` helper.
5. **Duplicated retry-write loop**: `writeEntireData` (lines 600-620) and the
   inner loop of `transferReaderToRemoteFile` (lines 318-339) both implement
   "seek, write slice, advance offset, throw if `written == 0`". Have the
   transfer loop call (an optionally progress-reporting) `writeEntireData`.
6. Minor: `Connection.swift:230-234` `generateLeaseKey`'s
   `withUnsafeBytes(of: UUID().uuid) { Data($0) }` closure is split across
   lines awkwardly — likely a formatting artifact, collapse to one line.
7. Minor formatting: trailing whitespace before some `// MARK:` comments
   (`Connection.swift` ~92, 247, 345) — confirm `format.sh` catches these.
8. Note: no leftover `DataPipe` cruft found in the transfer file — the
   post-refactor `BackgroundFileWriter`/`ReadAheadFileReader`/`TransferResult`
   code looks clean.
9. Style question (no action needed yet): `Connection-Conv-Transfer.swift`
   uses private free functions taking `on connection:` as first arg, while
   `Connection-Conv.swift` uses private extension methods. Both styles
   coexist — worth a short AGENTS.md note so neither gets "fixed" to match
   the other unnecessarily.

## File / Directory / Notify / Types / Operations

1. **Duplicated Protected-handle boilerplate**: `File.swift:128-141,428-439`
   and `Directory.swift:16-29,100-110` each reimplement
   "`Protected<T?>` + `requireHandle(operation:)` + `takeHandle()`". Factor
   into a small generic `ProtectedHandle<T>` helper shared by `File` and
   `Directory`.
2. **Non-atomic read-modify-write on `Protected` state**:
   `Notify.swift:551-554,614-624,637-642,645-651,654-660` — six places do
   `var state = protectedState.current; ...; protectedState.current = state`,
   which is two separate lock acquisitions and thus race-prone (e.g.
   `cancel()` vs `setPendingRequest`). Add `Protected.withLock { ... }` /
   `mutate { ... }` that does get+mutate+set under one `queue.sync`, and use
   it at all six sites — fixes a latent correctness issue while
   deduplicating.
3. **`File.OpenOptions.bridgeValue`** (`File.swift:75-93`) manually maps 5
   flags one-by-one with `if contains(...) { insert(...) }`, while
   `NotifyOptions`/`LeaseState` bridgeValue conversions use
   `OptionSet(rawValue:)` directly. If bit positions match, collapse
   `OpenOptions` to the same direct-rawValue pattern.
4. **Four near-identical delegate-dispatch methods**:
   `Notify.swift:301-330` — `notifyReceived`/`notifyStarted`/`notifyFailed`/
   `notifyCancelled` all do
   `callbackQueue.async { [self] in guard let delegate else { return }; delegate.notifyWatcher(...) }`.
   Factor a private `deliver(_ body: @escaping (any NotifyWatcherDelegate) -> Void)`.
5. **Three separate `Protected<Bool>` flags** (`Notify.swift:506-515`,
   `protectedDidFail`/`protectedDidFinish`/`protectedDidCleanUp`) plus a
   semaphore implement a small state machine. Consolidating into one
   `Protected<RunState>` enum (`.running`/`.failed`/`.cleanedUp`) would
   remove redundant locks and clarify `finish()`/`cleanUp()` ordering. (Ties
   into the `withLock`/`mutate` helper from item 2.)
6. **Repeated "create context → configure → configureCredentials" sequence**
   in `Operations.swift` across `listShares` (30-42), `connect` (64-81), and
   `parseURL` (90-98, minus credentials). A private
   `makeConfiguredContext(configuration:credentials:server:)` helper would
   remove the triplication.
7. Minor: `Operations.swift:101,134` — `configure`/`configureCredentials` are
   `internal` members inside a `public extension SMB`; consider whether they
   belong elsewhere (e.g. on `Connection` or as free internal helpers). Low
   priority.
8. No action needed: the bridge-enum→public-enum switch mappings in
   `Types.swift` (`Share.Kind.init`, `NodeType.init`,
   `NotifyChange.Action.init`) are repetitive but appropriately consistent —
   flagged only as "confirmed fine," not a problem.
9. Minor formatting: stray trailing whitespace in `File.swift` (~171, ~248,
   ~297) — `format.sh` should already handle.

## Error handling / Util

1. **Duplicated switch-case grouping** in `Error.swift:96-130` — the
   `operation` and `message` computed properties both repeat the same
   multi-case binding list (`.posix`, `.unknownPOSIX`, `.ntStatus`,
   `.unknownNTStatus`, `.unknown`), differing only in which tuple element is
   extracted. Factor a shared private `commonFields: (operation: String,
   message: String)?` used by both (~15 lines saved). This is the most
   impactful finding in this area.
2. **`PathValidation.swift:74,100-106`** — `Character.isAllowedSpecialChar`
   uses a closure-based `contains` over `allowedSpecialChars` when
   `String.contains(_: Character)` works directly:
   `allowedSpecialChars.contains(self)`. Also consider inlining the one-use
   `isAllowedSpecialChar` extension into `isValidSMBShareName`'s check.
3. Minor: `Error.swift:38-49` `posixErrorLocalizedDescription` is a
   single-use helper that duplicates pattern-matching already present in
   `debugDescription`'s switch; could be inlined into the `.posix` case.
4. Note (no action): `Error-Status.swift:1585-1587` force-unwraps
   `SMBStatusSeverity(rawValue:)!` — safe because the 2-bit mask has exactly
   4 values, all covered by the enum's cases, but worth a one-line comment
   stating the invariant explicitly.
5. No issues found in `Date+.swift`, `OptionSet+.swift`, `Protected.swift` —
   small, focused, idiomatic. `Error-InvalidArgument.swift`'s two large
   `description` switches are appropriately separate exhaustive mappings, not
   duplication.

## Suggested next steps (highest value, lowest risk first)

1. ~~Remove dead `waitForAllOperationsToEnd()` (Bridge #1)~~ — **false
   positive**: it's used by the public `disconnectGracefully()` as a sync
   barrier (syncing on the bridge queue blocks until in-flight bridge ops
   finish, since all bridge ops go through that queue). Left in place.
2. ✅ Removed no-op `catch { throw error }` in `itemExists` (Connection #1).
   Commit `8836ab6`.
3. ✅ Simplified `PathValidation.isAllowedSpecialChar` using
   `String.contains(_:Character)` (Error/Util #2). Commit `87f374c`.
4. ✅ Merged `operation`/`message` duplication in `Error.swift` into a shared
   `commonFields` (Error/Util #1). Commit `edd3551`.
5. ✅ Added `Protected.withLock` and used it for the five non-atomic
   read-modify-write sites in `Notify.swift` (File/Notify #2) — bundles a
   correctness fix (closes the cancel-vs-setPendingRequest race) with
   deduplication. Commit `73d9d81`.
6. ✅ Added `PendingOperationState.recordStatus`/`finish` helpers and applied
   them across the setStats, queryAttributes, resumeKey, copyChunk, open,
   lock, and makeLink Bridge callbacks (Bridge #2). Commit `27532d5`.
7. ✅ Factored `ProtectedHandle<Handle>` and used it for `Connection`,
   `File`, and `Directory` (File/Notify #1). Commit `a55b3e9`.
8. ✅ Consolidated `protectedDidFail`/`protectedDidFinish`/`protectedDidCleanUp`
   in `Notify.swift` into one `Protected<RunState>` struct (File/Notify #5),
   making `finish()`'s read of `didFail` and write of `didFinish` atomic under
   a single lock. Commit `835127b`.
9. ✅ Factored Bridge's four read/write variants to share a `withPointer`
   pointer-binding helper (Bridge #3). Commit `9bf7d89`.
10. ✅ Deduplicated transfer progress tracking into `ProgressTracker` and had
    `transferReaderToRemoteFile`'s write loop reuse `writeEntireData` with a
    per-block callback (Connection #4/#5). Commit `224ead1`.

Also noted but not addressed (lower priority, from the original findings):
- `BridgeTypes.swift` debug-formatting block could move to its own file

- AGENTS.md file-name references are stale vs. actual filenames (Bridge #6).
- `Connection-Conv.swift`'s duplicated `acceptedReadBlockSize`/
  `acceptedWriteBlockSize` var+method pair (Connection #3) — touches public
